# Windows release design

The release starts from upstream `v0.1.4` commit
`ea6cfecc65e0530c45b6d5ae08cffe52dda74a4a` in a separate clean worktree. The
accepted completion changes are reapplied as a reviewable changeset; no files
from the operational `runtime`, `runtime-probes`, local database, or logs are
copied into the public tree.

## Artifact layout

The single x64 Setup EXE contains:

- compiled JavaScript under `dist`;
- production-only Node dependencies;
- official Node.js 22.22.0 x64 runtime;
- portable lifecycle/health scripts under `runtime`;
- MIT attribution, complete generated dependency notices, and CycloneDX SBOM.

Inno Setup installs per-user to
`%LOCALAPPDATA%\Programs\QqCodexCompletionNotifier`. Application state is kept
separately in `%LOCALAPPDATA%\QqCodexCompletionNotifier` so repair can preserve
it and uninstall can remove it completely.

## Lifecycle

1. The user clicks the community Desktop shortcut.
2. A hidden Windows PowerShell 5.1 launcher resolves the Store ChatGPT package,
   safely replaces a running instance that lacks loopback CDP, and starts one
   audited Desktop main process.
3. A pinned Node process starts the attach-only bridge and waits for QQ gateway,
   health listener, completion monitor, and target readiness.
4. A watchdog binds to the Desktop main PID. It never restarts Desktop; after
   sustained absence it identity-checks and stops the bridge.

Repair reruns the cached installer. Uninstall stops only the recorded production
entry, removes shortcuts and application files, then removes the notifier's own
state directory. ChatGPT is untouched.

## Release outputs

- `qq-codex-completion-notifier-<version>-windows-x64-setup.exe`
- matching `.sha256`
- `release-manifest.json`
- source archive generated by GitHub

Publishing, repository creation, signing-secret enrollment, and final Release
approval are deliberately outside automated local work and require the owner.
